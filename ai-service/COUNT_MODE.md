# 购物篮数量确认模式

## 目的

默认识别接口按商品名称去重，适合返回“购物篮中有哪些商品”的结果，但不能直接表达同一商品出现了几件。购物篮收银需要保留每个独立检测框，再按名称汇总数量，因此新增可选的数量确认模式。

该模式面向近距离购物篮收银场景，不用于货架盘点。它只提供数量建议和确认依据，不绕过收银员确认，也不直接完成自动结算。

## 接口

在原有请求的基础上添加查询参数：

```text
POST /api/detect?count=1
Content-Type: application/json
```

请求体与默认接口一致：

```json
{
  "image": "data:image/jpeg;base64,..."
}
```

返回示例：

```json
{
  "items": [
    {
      "name": "可口可乐 500ml",
      "confidence": 0.9231,
      "box": [120, 80, 315, 560]
    }
  ],
  "counts": {
    "可口可乐 500ml": 1
  },
  "requires_confirmation": false,
  "auto_checkout_allowed": false
}
```

字段说明：

- `items`：当前图像中通过筛选的独立检测框；同名商品不会在此字段中合并。
- `counts`：按商品名称汇总的数量建议。
- `requires_confirmation`：出现重复商品，或任一检测置信度低于 `0.60` 时为 `true`，前端应要求收银员核对。
- `auto_checkout_allowed`：数量模式固定为 `false`，表示识别结果不能直接作为自动结算依据。

## 与默认接口的关系

不带 `count=1` 时，接口仍返回原有的商品名称列表，并继续使用原有的遮挡救援和跨帧投票逻辑。已有前端无需修改。

带 `count=1` 时，接口只依据当前帧保留独立检测框，不进行按名称去重，也不使用跨帧投票，以便收银员核对当前购物篮画面中的商品件数。

## 确认规则

数量模式采用“识别结果 + 人工确认”的流程：

1. 前端提交购物篮图像并读取 `items` 与 `counts`。
2. 前端展示商品名称、建议数量和检测框，收银员核对实物。
3. `requires_confirmation` 为 `true` 时必须确认或修正数量。
4. 确认后的数量再进入订单接口；不能依据 `counts` 自动完成结算。

## 已完成的本地验证

本分支的数量模式使用购物篮测试图进行验证。两张测试图均保留了 8 个独立检测框；重复商品测试能够按检测框数量汇总同名商品，并按规则进入人工确认流程。测试使用的本地模型和图片未提交到仓库。

## 当前限制

目标检测结果仍受拍摄距离、遮挡、反光、画面清晰度和训练样本覆盖范围影响。数量模式只能避免“按名称去重导致重复数量丢失”，不能保证低质量图像中的检测一定正确，因此保留人工确认是必要的业务约束。
